# Scraping and code review — 2026-09-05

This is the pre-fix review. See [the remediation record](crawl/SCRAPING_FIXES.md) for the implemented corrections and verification.

Reviewed the first-party C core, all three Python adapters, background runner and installation scripts, classifier, SQLite storage, export, and browser data/credits flow. Vendor internals were not audited. This is a review, not a patch: application code and the existing index were left unchanged.

P1 means a scraping control or central data guarantee is broken; P2 means a correctness/reliability issue that should follow those fixes. Reproductions used synthetic responses, a freshly compiled executable, and temporary databases, without running a live crawl.

## Findings

1. **[P1] External crawls bypass offline mode, caching, and request caps.** [adapter.c:159](crawl/src/adapter.c) builds the child command from its registered command and extra arguments; it never conveys `ctx->f->offline` or a remaining budget. OpenGameArt and game-icons issue their own urllib requests. A mocked `crawl gameicons --offline --max-requests 1` still launched the adapter with no arguments and reported zero network requests. On the real adapter that dispatch fetches GitHub. The initial daily-budget gate can block starting an online crawl, but once admitted, external requests are neither charged nor bounded by it. Give external adapters an enforced fetch/budget/offline contract; an offline external source without cached input should explicitly skip or fail.

2. **[P1] Native retries exceed both request caps.** [fetch.c:90](crawl/src/fetch.c), with the same defect at line 156 for HEAD. `budget_spent()` runs before the retry loop, not before each attempt. With both caps set to 1, an HTTP stub returning 503 produced **4 GET requests and 4 HEAD requests** in separate tests. Recheck/reserve allowance for every actual attempt, including retries.

3. **[P1] Native request charges disappear when a batch is interrupted.** [main.c:595](crawl/src/main.c) wraps checking in a transaction; crawling does the same at line 198. `charge()` updates the ledger on that same connection, so these writes are not independently committed despite the comments describing them as written through. A test showed a ledger of 4 before closing the uncommitted connection and 0 after reopening it. Thus interrupted runs lose progress and their request accounting together, allowing requests to be repeated. Separate durable accounting from long asset transactions, and handle transaction/accounting failures explicitly. This follows [SQLite transaction behavior](https://www.sqlite.org/lang_transaction.html).

4. **[P1] Enrichment applies a global budget once per source.** [main.c:650](crawl/src/main.c) calculates a limit once, then passes the same limit to every eligible adapter at line 678. With one pending Kenney asset and one pending OpenGameArt asset, `enrich --max-requests 1 --daily-cap 1` enriched both and recorded 2 requests. Carry a decreasing shared allowance across adapters. OpenGameArt also fetches robots.txt in addition to its asset pages, so charging only the number of jobs undercounts actual requests even for a single source.

5. **[P1] STOP does not stop an active batch.** [runner.py:183](crawl/runner/runner.py) checks STOP only before launching the blocking child command. Neither the C request paths nor the Python adapter request loops check that file. [STOP.cmd:11](crawl/runner/STOP.cmd) promises that current work exits after its current request, but the remaining batch continues. A 120-page OpenGameArt batch can continue for roughly 20 minutes at the fallback delay, longer with slow responses. Propagate cancellation and check it before each request and after waits.

6. **[P1] OpenGameArt keeps the least-permissive encountered licence.** [opengameart.py:197](crawl/adapters/opengameart.py) skips every slug already in the global `seen` set. The licence traversal is least-permissive first, so later CC0/CC-BY options never reach the core. A fixture appearing in both GPL and CC0 results emitted only GPL. This incorrectly excludes assets from the commercial/no-credit filters and defeats the stated last-write-wins design. Preserve licence alternatives or select the preferred verified option while deduplicating. OpenGameArt's administrator confirms that users can choose among an asset's listed licences in [this explanation](https://opengameart.org/forumtopic/multiple-license).

7. **[P1] robots.txt handling does not enforce robots rules.** [opengameart.py:117](crawl/adapters/opengameart.py) extracts the first Crawl-delay anywhere in the file, without matching user-agent groups or evaluating Allow/Disallow. A server error or timeout falls back to crawling. Kenney relies on a historical comment about a 404 and never retrieves current rules; the C checker also has no robots evaluation. [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.4) specifies group/path matching and treating unreachable robots files as complete disallow. Add cached robots policy enforcement for page scraping/checking, with explicit error handling. Current OpenGameArt robots content could not be retrieved through the research tool, so this finding concerns the code's behavior, not a claim that today's target paths are disallowed.

8. **[P1] Throttling responses do not reliably stop or delay subsequent requests.** [opengameart.py:180](crawl/adapters/opengameart.py) stops only the current combination after 429/503, then tries the next combination on the same host. Enrichment catches errors and continues to the next asset. A mocked 429 with `Retry-After: 3600` still led to the next combination and an exit status of 0. In C, [limiter.c:118](crawl/src/limiter.c) caps even an explicit server delay at five minutes, while `http.c` uses `atoi`, ignoring HTTP-date values. [HTTP Retry-After](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after) permits both dates and delay-seconds. Respect the full server delay, or stop/defer the host instead of retrying early.

9. **[P2] Transient HEAD failures permanently hide assets.** [main.c:540](crawl/src/main.c) records every returned status and treats all statuses >=400 as dead. A 403, HEAD-specific 405, or temporary 500/502 therefore hides a potentially live page from search and export. [store.c:657](crawl/src/store.c) only checks rows with `last_checked IS NULL`, so there is no normal retry or recovery after that classification, and recrawling does not clear it. Distinguish confirmed disappearance from blocked/unsupported/transient checks and schedule rechecks. No such false dead status was present in the current database: its checked rows were all 200.

10. **[P2] An unrecognized HTML page can be marked successfully enriched.** [opengameart.py:278](crawl/adapters/opengameart.py) emits an ID-only patch when no author or tags match; [store.c:168](crawl/src/store.c) sets `enriched=1` regardless. A synthetic HTTP-200 maintenance page produced exactly this patch and exit 0. Markup changes or challenge pages can therefore remove rows from the resumable queue without extracting data. Verify asset-page identity/structure and record retryable parse failure separately from valid-but-missing fields. The database has one enriched OpenGameArt row with missing required author, though its original cause cannot be established from the stored data.

11. **[P2] Failed/partial adapter work is reported as successful.** [opengameart.py:238](crawl/adapters/opengameart.py) and line 287 return 0 despite recorded failures. [adapter.c:205](crawl/src/adapter.c) also converts a failed child into success when it emitted some rows, and `cmd_enrich` ignores negative adapter results and returns 0. Thus the runner's failure status is unreliable. The all-429 fixture returned success with zero assets. Keep valid partial data, but propagate an incomplete/failure outcome through the CLI and runner.

12. **[P2] Task Scheduler installation uses a nonexistent parameter.** [install-task.ps1:45](crawl/runner/install-task.ps1) passes `-StopIfGoingOnBatteries`. The installed cmdlet exposes `AllowStartIfOnBatteries` and `DontStopIfGoingOnBatteries`, not this parameter. This was verified by read-only parameter inspection and matches [Microsoft's reference](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasksettingsset). Installation will fail before registration. Use the supported setting/default for stopping on battery; no scheduled task was created or changed during review.

13. **[P2] Kenney refresh replaces good curated data after a partial failure.** [kenney.py:197](crawl/adapters/kenney.py) rebuilds each entry from only its slug and generated name; line 214 overwrites the JSON even if a later page timed out. A fixture with two existing packs, one successful listing page, then a timeout returned success, removed the unseen pack, and discarded the retained pack's custom name, thumbnail, and type. Merge retained metadata and only replace the catalogue after confirmed complete enumeration; write atomically.

14. **[P2] WinHTTP read errors are returned as successful truncated responses.** [http.c:183](crawl/src/http.c) treats a false return from either read API like EOF, then sets `rc=0`. The fetcher can cache the partial body with its validators; subsequent 304 responses can keep serving that unusable body. [Microsoft documents](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpreaddata) that FALSE is an error, distinct from successful EOF. Return transport failure on read errors and never cache an incomplete response. Confirmed by code/API review; not fault-injected against WinHTTP.

15. **[P2] Global uncreditable counts can starve link checking indefinitely.** [runner.py:135](crawl/runner/runner.py) chooses OpenGameArt enrichment whenever the global uncreditable count is nonzero, even if OpenGameArt has nothing actionable left. The database already contains two uncreditable game-icons rows, a source without enrichment. A fixture with only those two unresolved credits and 100 unchecked links still selected OpenGameArt enrichment. Once its queue is exhausted, repeated no-op jobs take priority over link checks and still consume the runner's booked allowance. Choose work using per-source actionable backlog and fall through when a queue has no eligible rows.

## Documentation uncertainties and follow-up checks

- ambientCG's [current v2 documentation](https://docs.ambientcg.com/api/v2/full_json/) documents limits of 1–250, whereas the adapter requests 1000 and assumes a shorter response means the final page. However, the local cache contains 1000, 1000, and 877 assets for those exact URLs, totaling 2877. Historical behavior is therefore demonstrated, while current documented behavior differs. Do not silently change pagination based on either assumption; verify a bounded current response before patching. Likewise, documentation contradicts the repository's claim about invalid `type` values. No live API crawl was run to settle this discrepancy.
- User-Agent contact links still point to `github.com/example/magpie`, and the C UA includes `contact@example.com`. Supply real project/contact details before unattended operation.
- HTML regexes, taxonomy IDs, hardcoded author/licence maps, and Poly Haven's inferred per-type formats have no stored source snapshots or dedicated fixtures in the project. Their full current accuracy was not established by this review. The four cache entries cover only the native API sources.
- Request accounting is not an atomic reserve-and-check operation across simultaneous processes. The in-memory daily counter is loaded once, and SQLite errors are frequently ignored. Concurrency and midnight rollover need explicit tests when repairing the ledger. The shared `.gas-enrich.tmp` filename also needs isolation if concurrent runs are supported.
- Broader data maintenance issues include keeping the longer tag string on recrawl rather than the freshest authoritative tags, and never scheduling normal rechecks of previously checked URLs. These deserve targeted regression fixtures when the scraping path is repaired.

## Plan

Fix the network guarantees first: external adapter controls, per-attempt/shared caps, durable accounting, STOP, robots, and throttling. Then fix licence selection and response validation, followed by truthful completion status, recoverable link checks, runner scheduling/installation, and safe Kenney refresh. Keep the adapter architecture; these findings do not justify an unrelated rewrite. Add focused synthetic regression tests around each corrected failure path before attempting a bounded live validation.
